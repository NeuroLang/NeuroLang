2. For "Is X a druggable gene?", return one row per drug that targets X, with drug name, approval flag, linked targets and max clinical trial phase. Take the rows from the drug table, matching X as a whole symbol in the targets string. Do not return a boolean, and do not rely on the indication table's target column.

Return SNP, p and b, ordered by p and limited to 100 rows, and do not filter on sign or threshold. Do not use SMR or prior-probability tables for these questions.

For SMR questions such as "top SNP", "most significantly associated" or "association signals", apply the significance threshold (p_SMR_multi below the threshold, and consider HEIDI) so that the result is empty when nothing is significant. 10. When ranking SMR hits, order by p_SMR_multi, the adjusted multi-SNP p-value, rather than the single-SNP p. Return topRSID, disease, tissue or omic type, p_SMR_multi, p_HEIDI, alleles, frequency and the functional-significance label, filtering on the exact tissue and omic dataset named in the question.

11. Map tissue and dataset phrases from the question to the database's own values by checking the actual tissue and omic names. Use the disease abbreviations the database uses, such as AD, PD, LBD, PSP and ALS. Gene-specific SMR questions should return all matching rows for the gene, not only a single minimum.

12. For "nearest gene to SNP", query the nearest-gene table or tables for that SNP and return source_table and nearestGene. Always produce a valid, non-empty query, and use all relevant tables where the data is split across them.
